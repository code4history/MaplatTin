## 不変条件を分ける

数学上、正の一様倍率・回転・平行移動は各折れ線の累積長比を変えない。両面に別々の相似変換を適用してよい。異方性倍率・剪断は一般に比を変えるので、この不変条件には含めない。向き反転は端点と内点列を**両面同時に**反転し、rを1-rに変える。

| 条件 | 合否の扱い |
|---|---|
| 固定された有限・正全長入力に対する対応の1対1性、添字の厳密増加 | DP契約。無条件な座標x/y単調性とは異なる |
| 許容幅内の順序付き対応数が最大、同数なら比差合計最小 | 小規模列を独立全列挙して検査。DP実装をコピーしない |
| 全出力列の順序 | 比の昇順に加え、軸上の生成例では両面の進行方向の単調性を検査。曲線一般では座標単調性を要求しない |
| 元折れ点の座標保存 | 対応成立時は各面の元座標をそのまま保存。明確に分離した未対応折れ点も保持。許容幅内の余りの全保存は現仕様では要求不可 |
| 相似変換で中継点数・対応が不変 | 実数演算では成立。binary64では候補集合の境界を越え得るため条件付き。厳密dyadic変換群は強い合否、任意角・大原点群は数値品質の仮説を検証する探索として区別 |
| 面交換・反転で同じペアが選ばれる | 最適解が一意で候補集合が安定している場合に限定。同コストの別解を不具合扱いしない。DP群ではペアID同一ではなく最適スコアを比較 |
| r' = 1-r | 実数では成立。反転後の累積和の丸め順が変わるので一般入力でビット一致不可。厳密dyadic群だけ完全一致を要求 |
| 完全同一座標の重複 | 同じ点対のゼロ長セグメントは幾何的には冗長。両面同時の重複挿入を正規化して同じ出力にする契約を提案。現実装は未達 |
| 片面だけ同一点・他面では別点 | 全点を残したまま単射の対応にはできない。省略／入力拒否／精度不足通知の方針が必要。勝手に一点へ統合すればよいとはしない |
| TIN構築可能性 | 非交差制約、異なる頂点、非零面積、十分な分離がある入力で要求。全有限入力や退化入力について成功を要求しない |
| 三角形の接続やcompiledハッシュの一致 | 生成変換群には要求しない。同円周上の点・数値摂動で対角線が変わり得る。制約辺存続と有効な三角形を比較する |

k=4は実測で選ばれた係数で、全折れ点数に対する誤差上界の証明ではない。全長誤差には各セグメントの量子化・距離計算・累積和が関与し、折れ点数や折り返し具合にも依存する。現在の上限1e-9を越える領域では「本来同一の比を必ず統合」も保証できない。大原点を引いて計算しても入力時点で失った下位ビットは復元できない。

また、許容幅内であるという関係は推移的とは限らない。A≈B、B≈CだけでA≈Cとして全点をまとめるoracleは使わない。実装と同じ許容幅で「正解」を判定するだけでは係数不足を発見できないため、生成相似変換群は生成時の対応を別に保持する。

## ファイルと使い方

- `tests/edge-nodes-generated-cases.ts`：Node/Vitest共用の生成と独立oracle。
- `tests/edge-nodes-generated.test.ts`：Vitest登録、任意の診断JSON出力、提案契約のopt-inプローブ。
- `tests/edge-nodes-generated-tin.test.ts`：24生成入力×V2/V3×向き反転＝96統合ケース（未実行）。紙面whの範囲を維持し、地理面のGCPと折れ点を同じ変換で動かす。存在する三角形、有限座標、非零面積、両方向の全制約辺を検査。
- `run-core.mjs`：今回実行した依存不要の単体ランナー。
- `minimize.mjs`：失敗1件を対応内点同時削除で縮小する補助スクリプト。
- `core-results.json`：全失敗の完全座標、診断66件、実行環境。
- `reduced-counterexample.json`：縮小入力と実出力。
- `src/edge-nodes.ts`：取得した固定commitの検証用コピー。**既存リポジトリのsrcへ上書きしない**。
- `source-sha256.txt`：ソースのファイルハッシュ。

既に依存が導入済みのローカルリポジトリを使う場合、ローカル開発LLMが独立した検証用コピーを用意し、対象SHAを照合してからtestsの3ファイルだけを配置する。既存ブランチへ反映・コミット・push・リリース操作はしない。

```bash
git rev-parse HEAD
# 期待値: 3ddc4e956a509834d6dca9190ce69e9a8fadd2c9
# 以下は検証用コピーのルートで実行
EDGE_SEED=20261128 EDGE_CASES=2000 EDGE_REPORT=/tmp/maplat-edge-survey.json pnpm exec vitest run tests/edge-nodes-generated.test.ts
pnpm exec vitest run tests/edge-nodes-generated-tin.test.ts
EDGE_PROBE=1 pnpm exec vitest run tests/edge-nodes-generated.test.ts -t 'duplicate insertion'
pnpm exec tsc --noEmit --allowImportingTsExtensions
pnpm exec eslint tests/edge-nodes-generated-cases.ts tests/edge-nodes-generated.test.ts tests/edge-nodes-generated-tin.test.ts
```

Vitest/TypeScriptの版は対象package.json/lockfileに従う。fast-check等の追加パッケージは不要。依存がない環境では、対象リポジトリの既存standalone手順と固定lockfileを確認して環境を用意する（未確認の最新版を追加しない）。今回のAPI検査はソースと既存試験に基づくが、Vitestでの読み込み・型検査が通ることまでは未確認。

同梱スナップショット単体で今回の実行を再現する場合：

```bash
# 展開したパッケージのルート。実行確認したNodeはv24.22.3
EDGE_SEED=20261128 EDGE_CASES=2000 node --experimental-strip-types run-core.mjs
# 現スナップショットでは11ケースの失敗を報告し終了コード1
node --experimental-strip-types minimize.mjs
```

実行結果JSONは各実行で上書きするため、比較するログは別名で保存する。Vitest版は既定200ケース/群のため、上記再現にはEDGE_CASES=2000が必要。skipされるのは提案契約の重複プローブだけで、通常の生成失敗を握りつぶさない。surveyの通過は「退化入力でも正しい」という意味ではない。

## ローカル開発LLMへの引き継ぎ

1. SHAを確認し、まず変更なしで上記を再現。型エラーやテスト側の誤りは実装不具合と区別する。
2. `similarity ... case=300` と縮小例について、両方向の比列、許容幅、対応ペア、生成点の片面／両面重複を記録。現在の実装に合わせて期待値を14へ変更しない。
3. 縮小例を単独のVitest fixtureに固定し、TIN統合に使うには外枠GCPと紙面boundsを整合させる。例外だけでなく制約辺欠落・非有限座標・零面積を記録。相似変換前後のハッシュ一致は求めない。
4. seedを増やす際は、原点の符号・2の冪境界、両面の倍率を独立に振る。間隔縮小は候補が一意／候補が複数／入力が量子化で一致の3領域に分ける。今回の有限グリッドを網羅性の証明としない。
5. 非等方倍率、自己交差、非有限入力、全長0、演算のoverflow/underflowは別の契約群。今回の正常相似変換の成功条件に混ぜない。
6. 不具合修正や精度不足時の仕様変更はこの依頼の範囲外。係数変更だけで終わらせず、保存と重複回避の両立条件を検討し、人間に結果を返す。既存48ハッシュを再生成しない。
