# MaplatTin TIN Construction Notes

This note explains how the current `Tin` implementation stitches together the triangulated network, with a focus on one behavior that is easy to overlook: the synthetic boundary vertices (`b0`–`b3`).

## High-Level Update Flow

1. `Tin.updateTin()` (`src/tin.ts:656`) first prepares the inputs. V3 (the default) derives the working bounding box from the GCPs (`computeGcpBbox`, `src/tin.ts:681`–`682`). V2 (`useV2Algorithm`) calls `validateAndPrepareInputs()` (`src/tin.ts:599`) to confirm every forward GCP lies inside the working bounds derived from `wh`.
2. `generatePointsSet()` (`src/tin.ts:430`) converts each GCP into paired GeoJSON points and expands constraint edges. Intermediate edge nodes inherit IDs like `e0`, `e1`, … so they can participate in the triangulation.
3. Two constrained triangulations are produced with `constrainedTin()`—one for forward coordinates, one for backward (`src/tin.ts:699`–`708`). The backward side is rebuilt independently only when strict mode degrades into “loose”.
4. The centroid (`c`) is the forward GCP centroid (`src/tin.ts:714`), transformed through the forward triangulation to obtain its backward position (`src/tin.ts:757`–`760`). The convex hulls of both planes are collected into `convexBuf` (`src/tin.ts:715`–`752`). The boundary vertices are then computed by `calculatePlainVertices()` or `calculateBirdeyeVertices()` (selected at `src/tin.ts:838`).
5. For V3 the vertices are searched over margins (`searchBoundary`, `src/boundary-search.ts`) and the triangulation is built with every convex-hull edge constrained, dropping only the hull edges that break `strict` (`buildWithHull`, `src/tin.ts:915`). Vertices are added to the point set and indexed TIN helpers are prepared.
6. For V3, hull edges that still had to be dropped get a **supplement pair** (`buildWithSupplements`, `src/tin.ts`; geometry and the trial loop in `src/supplement-pairs.ts`). See “Supplement Pairs” below.

## Supplement Pairs (V3, #89)

A hull edge A–B that was dropped to keep `strict` is the edge of an inner triangle (A, B, P) that flips in the geographic plane (P′ falls outside A′–B′). Auxiliary-vertex triangles then cut into the hull. Constraining A–Q and Q–B instead, for a point Q just outside A–B, removes the problem as long as Q′ is placed where every triangle around Q keeps the majority orientation.

1. **Find.** After `buildWithHull`, if the result is `strict`, the dropped hull edges are the paper-plane hull edges (`boundary.forwHull.all`) that are not edges of the adopted triangulation (`analyzeMesh`). None → nothing is done and the result is bit-identical to a build without the feature. Not `strict` → nothing is added.
2. **Paper position** (`proposeSupplementCandidate`). S = points whose geographic position is outside A′–B′ and whose foot on the chord lies inside it on both planes; P\* = the one farthest from A′–B′. Q = the foot of P\* on A–B, moved outward by `SUPPLEMENT_EPSILON` (1e-4) × the chord length (a point exactly on the chord ends up slightly inside or outside in floating point). If S is empty, the chord midpoint is used.
3. **Geographic position** (`fitToKernel`). Q′ lies on the ray `F′ + s·n` (F′ = foot of P\*′ on A′–B′, n = outward unit normal). Build the triangulation with every hull edge constrained (the first attempt of `buildWithHull`, no kink search), take the triangles around Q, and intersect the half-planes “orientation equals the majority” in `s` to get `[lo, hi]` (the kernel cut by the ray). `s = max(lo, 0) + m`, `m = min(max(λ·max(lo, d\*), μ·|A′B′|), (hi − lo)/2)` with λ = `SUPPLEMENT_LAMBDA` (0.25), μ = `SUPPLEMENT_MU` (0.01), d\* = the protrusion of P\*. The ring changes when Q′ moves, so this repeats up to `MAX_KERNEL_FIT_ITERATIONS` (4) times. An empty kernel rejects the edge.
4. **Try** (`addSupplementPairs`). Add one candidate per dropped edge at once (a point whose kernel is empty is left out); accept only if the result is `strict` and every added point is a hull vertex whose two hull edges are triangulation edges. Otherwise try edge by edge (one point, then several points taken from the upper hull of the protrusions along the chord), then repeat for the edges that remain. Limits: `MAX_SUPPLEMENT_PAIR_ROUNDS` (4) rounds, `MAX_SUPPLEMENT_PAIRS` (32) points, each hull edge (by its end points on the paper) tried once. Nothing accepted → the state before is restored. **Effort budget:** the procedure may spend `SUPPLEMENT_BUDGET_FACTOR` (1) × the effort of the first triangulation (number of attempts of `buildWithHull`), a placement trial counting `SUPPLEMENT_MEASURE_COST` (0.4); a rebuild gives up when it would exceed the remainder (at most one attempt beyond). Hull edges with many nearby points (a jittered grid) used to cost 10–33× in per-edge retries; now the procedure gives up there and keeps the result without supplement pairs. A point whose kernel is empty is dropped from the batch instead of discarding the whole batch. The placement trial is run once and the batch is built straight away (the verifying re-measure is only done when the build fails); when the batch is `strict` but some added points are ineffective, only those points are dropped and the batch is built again. **For inputs with many dropped hull edges (dense jittered grids), the procedure may give up because of this budget; the result is then identical to a build without supplement pairs (#91).**
5. **Not an input.** Supplement pairs are appended after the edge nodes of `rawPointsSet`, `allGcps` and `this.edgeNodes` as `e{n}`, but not to `pointsSetFC`/`convexBuf`, so the centroid and fan estimate see only human GCPs and edge nodes. `generatePointsSet()` rebuilds `edgeNodes` on every `updateTin()`, so nothing is carried over. `loose` does not run the procedure (MaplatTin#95): the strict trial it would need first costs 4–14× the time. `supplementPairs: false` skips it too.

## Boundary Vertex Completion (`calculatePlainVertices`)

The `Tin` needs extra control points (`b0`–`b3` for the four bbox corners; V3 adds up to 32 more on the bbox sides) so the forward and backward planes share an enclosing polygon. The implementation is `calculateVerticesCore()` in `src/boundary-vertices.ts:427`–`616`.

1. **Collect convex hull samples.** `convexBuf` maps each convex-hull vertex (forward space) to its transformed partner (backward space). The map is built from both the forward and backward convex hulls to ensure coverage even when the transformation is skewed (`src/tin.ts:718`–`752`). `collectSamples()` (`src/boundary-vertices.ts:41`) turns each entry into the pair of vectors from the centroid (backward `y` is flipped).
2. **Estimate scale and rotation.** `buildVertexRatio()` (`src/boundary-vertices.ts:167`) reduces the samples to one `[scale, theta]` pair (plain) or one per quadrant (birdeye). The estimator depends on the format:
   - **V3 plain (`"farLsq"`, `reduceSamplesFar()`, `src/boundary-vertices.ts:160`).** Only the hull points whose paper distance from the centroid is at least 0.6 × the farthest are used (`FAN_FIT_FAR_RATIO`), and a centroid-fixed similarity `F ≈ z·B` is fitted by least squares (`F`, `B` = paper / geographic deltas from the centroid as complex numbers; `z = Σ F·conj(B) / Σ |B|²`; scale `|z|`, rotation `arg z`). The weight is `|B|²`, so the pointing error of hull points near the centroid hardly matters. This replaces the minimum ratio, which picked the largest negative error among near-centroid hull points and amplified it up to the paper corners (24 GCPs with 3 px error: outer maximum 109.5 km → 18.7 km on the demo material).
     - **Fewer than 3 far points** (`FAN_FIT_MIN_POINTS`, e.g. maps with 4–6 GCPs): the same fit is applied to all hull points.
     - **Fall back to the legacy estimate** when the fit does not describe the data: the agreement `|Σ F·conj(B)| / √(Σ|F|²·Σ|B|²)` (0–1, 1 for a perfect similarity) is below 0.5 (`FAN_FIT_MIN_AGREEMENT`), or the samples are empty / all coincide with the centroid. A geographic plane that is mirrored relative to the paper makes `Σ F·conj(B)` cancel, so `|z|` becomes a tiny positive number and the vertices would fly arbitrarily far; the agreement is near 0 there. Measured agreement on regular inputs: demo materials ≥ 0.9996, real maps 0.90–1.00, thinned real maps (4–6 GCPs, 234 sets) min 0.79 / median 0.9986.
   - **V2 and birdeye (`"min"`, `reduceSamples()`, `src/boundary-vertices.ts:78`).** Unchanged: the scale is the smallest paper/geographic distance ratio and the rotation is the unweighted mean angular offset (birdeye per quadrant; a missing quadrant falls back to the shared ratio, `src/boundary-vertices.ts:167`–`190`).
   - Whether the estimator is the new one (`RatioEstimator`) is independent of whether edge vertices are created (`withEdgeVertices`): `calculatePlainVertices(params, v3)` uses `"farLsq"` only for V3, and `calculateWorldFileVertices()` does not estimate at all (the geographic side is fixed by the world file).
3. **Place the four corner vertices.** Each bbox corner is transformed with `computeVertexBakwFromRatio()` (`src/boundary-vertices.ts:212`): the distance from the centroid in forward space is divided by the scale and the angle is rotated by `theta`.
4. **Expand to enclose every point.** `checkAndAdjustVerticesN()` (`src/boundary-vertices.ts:347`) tests rays from the centroid through every GCP and edge node against the backward polygon; if a point lies outside, the two vertices of the crossed side are scaled outward until it is enclosed. It runs on the four corners and again on the full set. This keeps the GCPs inside the ring even when the scale estimate is optimistic.
5. **V3 only: edge vertices.** For each of the 36 ten-degree bins without a corner, the farthest interior point decides a forward point on the bbox boundary, whose backward position is placed on the corner polygon in the interpolated direction (`src/boundary-vertices.ts:520`–`602`). Results are sorted by forward angle (`src/boundary-vertices.ts:604`–`614`).

6. **V3 only: ring repair when `strict` fails.** If `strictMode` is `strict` or `auto`, the first build established an outer boundary, and the result is still not `strict` (after dropping hull edges and adding supplement pairs), Tin repairs the ring of auxiliary vertices. (If no boundary was established, as when a world file outer ring falls back to the fan, nothing is repaired.) The 36-bin vertices are extrapolated from the fan and can overlap interior triangles where the hulls of the two planes disagree (a mispointed GCP is a hull vertex in one plane only); edge flips cannot undo that. (a) **Thinning** (`ringRescue: "thinned"`): the auxiliary vertices of triangles that flip or overlap in the geographic plane (`src/ring-culprits.ts`) are dropped together with their two neighbouring 10° bins (`BoundaryVerticesParams.ring.skipBins`) and the mesh is rebuilt, up to `MAX_RING_ROUNDS` (4) times. It gives up on thinning when 24 of the 36 bins (2/3) would be dropped, or when dropping makes the boundary fail. Once `strict`, each dropped run of bins is put back once, keeping the put-back if `strict` still holds, so only the bins `strict` needs stay dropped. (b) **Corners only** (`ringRescue: "corners"`): otherwise only the four corner vertices are kept, with V3's scale/rotation estimate (`farLsq`), not V2's `min`. The effort (mesh builds) is capped at `RING_RESCUE_BUDGET` (4) times the first attempt's for the search including stage (b), and `RING_RESTORE_BUDGET` (8) times including the put-back trials (checked only before a trial starts, so the last trial can exceed the cap); when a world file outer ring falls back to the fan, the base is the fan's first build. A repair is adopted only if it is `strict`; otherwise the first result is restored unchanged, so some inputs that are `strict` under V2 stay `strict_error` (about 0.2% of random inputs). A dropped run of bins can deviate from the 36-bin extrapolation more than the four corners would; thinning goes first because it leaves no intrusion of auxiliary triangles into the hull, keeps the geographic-plane intrusion small, and leaves every bin outside the dropped runs identical to the 36-bin result. The same repair applies to the world file outer ring (`outerTransform: "worldFile"`); `vertices_points` then lists the whole repaired ring (MaplatTin#98).



*Birdseye mode:* When `vertexMode` is `Tin.VERTEX_BIRDEYE` and convex hull samples exist in all four quadrants, the algorithm keeps those per-quadrant scale/rotation pairs. If any quadrant lacks data, it gracefully falls back to the shared-factor approach so warped projections remain stable (`src/boundary-vertices.ts:167`–`190`).

The outcome is a set of synthetic points that safely enclose all transformed geometry while roughly preserving local rotation and aspect.

## Weight Buffer (Removed)

Removed in 2.00704: in-triangle interpolation is now pure affine.

## Related Observations

- Strict mode (`MODE_STRICT`) attempts to reuse the forward triangulation for the inverse transform. When edge intersections are detected, the status downgrades to `STATUS_ERROR` and the backward mesh is recomputed.
- Before declaring `strict_error`, strict mode now rebuilds shared-edge triangles by reusing the legacy overlap-repair workflow (search index mutation, triangle replacement, and revalidation) so healable overlaps stay in `STATUS_STRICT` (`src/strict-overlap.ts`, `resolveOverlaps` called from `src/tin.ts:393`–`400`).
- The asynchronous wrapper `updateTinAsync()` used by the tests simply delegates to `updateTin()` in a `Promise`. There are no real async dependencies in the pipeline, which is why the next iteration intends to simplify it.

These notes should help guide the upcoming cleanup: we can confidently document or refactor the bounding vertices and the redundant async surface without changing behavior.
