# tin-v3-data-model 仕様

## ADDED Requirements
### Requirement: V3 は編集用 payload と配布用 payload を区別しなければならない
このパッケージは、編集ワークフロー向けの情報量の多い payload と、ランタイム専用の軽量 payload を別クラスとして定義しなければならない。

#### Scenario: 編集用 payload を export する
- **GIVEN** GCP と制約エッジから構築された `Tin` インスタンスがある
- **WHEN** パッケージが編集用 payload を export する
- **THEN** その payload は、制御点、エッジ定義、および編集に必要なメタデータを含め、三角網を点検・修正・再 export するために必要な情報を保持しなければならない

#### Scenario: 配布用 payload を export する
- **GIVEN** 妥当な編集用 payload がある
- **WHEN** パッケージが配布用 payload を export する
- **THEN** その payload は、ランタイムが座標変換およびビューポート転送を行うために必要な全フィールドを保持しつつ、編集専用の構造を削除しなければならない

### Requirement: V3.1 開発中は Tin が生成と単独座標評価の両方を担わなければならない
V3.1 フォーマット開発中、このパッケージは CRS 対応 payload について、フォーマット生成と単独座標評価の両方を担わなければならず、それにより候補フォーマットを生成から評価まで一体で判断できなければならない。

#### Scenario: 開発者が候補 V3.1 payload を比較する
- **GIVEN** 同じ元データセットから V2、V3、V3.1 payload を生成できる
- **WHEN** 開発者がそれらの座標変換挙動を比較評価する
- **THEN** `@maplat/tin` は、その同じパッケージ文脈で候補 payload を生成し、単独座標変換を評価できなければならない

#### Scenario: V3.1 契約が受理された
- **GIVEN** V3.1 payload 契約が受理されている
- **WHEN** ランタイム責務を見直す
- **THEN** このパッケージは、単独座標評価経路を `@maplat/transform` へ移管できなければならない

### Requirement: V3.1 イニシャライザは CRS 対応 GCP 入力をサポートしなければならない
V3.1 イニシャライザは、`[[絵図座標, 地図座標], ...]` 形式の GCP 群と、地図座標の入力 CRS を示す任意の指示子を受け付けなければならない。

#### Scenario: CRS メタデータが省略される
- **GIVEN** `gcps` が与えられ、`crs` フィールドが省略された V3.1 イニシャライザ呼び出しがある
- **WHEN** パッケージが入力地図座標を保持する
- **THEN** その入力地図座標は `EPSG:4326` として解釈されなければならない

#### Scenario: CRS メタデータが明示される
- **GIVEN** `gcps` と `crs: { code, text }` を持つ V3.1 イニシャライザ呼び出しがある
- **WHEN** パッケージが入力地図座標を保持する
- **THEN** パッケージは、宣言された入力 CRS を保持しつつ、必要に応じてその座標を現在の地図座標状態へ変換しなければならない

#### Scenario: 呼び出し側が現在の地図 CRS を要求する
- **GIVEN** `crs: true` を持つ V3.1 イニシャライザ呼び出しがある
- **WHEN** 地図としての現在 CRS がすでに確定している
- **THEN** パッケージは、その入力地図座標をその確定済み CRS として解釈しなければならない

#### Scenario: 地図 CRS 確定前に現在の地図 CRS を要求する
- **GIVEN** `crs: true` を持つ V3.1 イニシャライザ呼び出しがある
- **WHEN** 地図としての現在 CRS がまだ確定していない
- **THEN** パッケージは、別 CRS を黙って選ばず、エラーにしなければならない

### Requirement: V3.1 は未確定の地図 CRS 状態をサポートしなければならない
V3.1 ランタイムは、地図 CRS とワールドファイル値がまだ確定していない状態をサポートしなければならない。

#### Scenario: 地図 CRS が未確定である
- **GIVEN** GCP は与えられているが、地図 CRS とワールドファイル値がまだ確定していない
- **WHEN** パッケージがその作業状態を保持する
- **THEN** 地図側 GCP 座標は `EPSG:4326` 正規化形で保持され、三角網はまだ生成してはならない

#### Scenario: 地図 CRS が確定する
- **GIVEN** 地図 CRS とワールドファイル値が確定している
- **WHEN** パッケージが作業状態を再構築する
- **THEN** パッケージは、その確定 CRS とワールドファイル配置から地図座標系を導出し、そのうえで三角網を構築するかどうかを判断しなければならない

### Requirement: V3.1 は CRS とワールドファイル値を明示的要求時のみ推定しなければならない
パッケージは、呼び出し側が明示的に推定処理を要求した場合にのみ、GCP から地図 CRS とワールドファイル値を推定しなければならない。

#### Scenario: 推定要求なしで GCP が編集される
- **GIVEN** 呼び出し側が GCP を追加、削除、または更新する
- **WHEN** 明示的な CRS 推定コマンドが呼ばれていない
- **THEN** パッケージは、地図 CRS やワールドファイル値を自動で再計算してはならない

#### Scenario: 明示的に推定処理が呼ばれる
- **GIVEN** 呼び出し側が明示的に CRS 推定を要求する
- **WHEN** パッケージがその推定器を実行する
- **THEN** パッケージは、全地図側 GCP 座標を `EPSG:4326` に正規化し、候補投影座標系を列挙し、各候補に対してまず等方スケール・回転・並行移動からなるワールドファイル値を当てはめ、せん断最適化前の変換残差分散が最小の候補を採用しなければならない

### Requirement: CRS 探索とせん断最適化は別段階でなければならない
パッケージは、CRS の選定処理とせん断値の当てはめ処理を別段階として扱わなければならない。

#### Scenario: 利用者が CRS を指定する
- **GIVEN** 利用者が対象地図の CRS を明示的に指定している
- **WHEN** パッケージがワールドファイル値を推定する
- **THEN** パッケージは、まずその CRS 上で等方スケール・回転・並行移動を当てはめ、その後にせん断を追加最適化してもよい

#### Scenario: 候補から CRS を探索する
- **GIVEN** パッケージが候補 CRS 群の中から 1 つを選ぼうとしている
- **WHEN** 各候補 CRS を採点する
- **THEN** 各候補の採点は等方スケール・回転・並行移動だけで行われ、せん断は候補選択へ影響してはならない

#### Scenario: 探索または指定により CRS が確定した
- **GIVEN** 地図 CRS が利用者指定または候補探索により確定している
- **WHEN** パッケージが最終的なワールドファイル最適化を行う
- **THEN** パッケージは、その確定 CRS と、すでに求めた等方スケール・回転・並行移動の結果を前提に、後段の微調整としてせん断を当てはめられなければならない

### Requirement: 推定診断情報はデバッグ専用でなければならない
パッケージは、候補 CRS の採点結果や残差などの診断情報を、通常運用データの一部ではなく、明示的なデバッグモードでのみ扱わなければならない。

#### Scenario: デバッグモードが無効である
- **GIVEN** 呼び出し側が推定診断出力を有効にせず CRS 推定を実行する
- **WHEN** パッケージがその結果状態を返却またはシリアライズする
- **THEN** 候補一覧、採点詳細、同種の推定診断情報は通常出力から省略されなければならない

#### Scenario: デバッグモードが有効である
- **GIVEN** 呼び出し側が推定診断出力を有効にして CRS 推定を実行する
- **WHEN** パッケージがその結果状態または診断情報を返す
- **THEN** パッケージは、候補 CRS ごとの採点、選定された CRS の評価文脈、せん断前後の残差情報を検査用に含めてもよい

### Requirement: CRS 推定は明示的かつ分解可能なメソッド群として提供されなければならない
パッケージは、CRS 推定の明示的な入口メソッドを提供し、同時にその推定ワークフローを再利用可能な小さなメソッド群へ分解できなければならない。

#### Scenario: 呼び出し側が完全な推定を実行する
- **GIVEN** 呼び出し側が GCP から地図 CRS とワールドファイル値を推定したい
- **WHEN** 呼び出し側が `estimateMapCrs()` のような明示的入口メソッドを呼ぶ
- **THEN** パッケージは、initializer や点更新メソッドの暗黙副作用に頼らず、完全な推定フローを実行しなければならない

#### Scenario: 候補 CRS 列挙を独立にテストする
- **GIVEN** 地理座標へ正規化済みの GCP 群がある
- **WHEN** 呼び出し側またはテストが候補 CRS 列挙 helper を呼ぶ
- **THEN** パッケージは、後続の fitting 段階と独立して候補 CRS 一覧を返せなければならない

#### Scenario: world_file_basic 推定を再利用する
- **GIVEN** 固定された CRS と GCP 群がある
- **WHEN** 呼び出し側またはテストが、等方スケール・回転・並行移動を当てはめる helper を呼ぶ
- **THEN** パッケージは `world_file_basic` を独立して計算できなければならず、その same helper を利用者指定 CRS ケースと候補探索ケースの両方で再利用できなければならない

### Requirement: 初期 V3.1 の CRS 推定対象は日本向け候補集合に限定されなければならない
初期推定器は、候補投影座標系を明示的にサポートされた日本向け集合へ制限しなければならない。

#### Scenario: 推定器が候補を列挙する
- **GIVEN** 初期 V3.1 推定器が実行される
- **WHEN** 候補投影座標系が列挙される
- **THEN** 候補集合は `EPSG:3857`、WGS84 UTM、WGS84 系日本平面直角系、TOKYO datum UTM、TOKYO datum 日本平面直角系に限定されなければならない

### Requirement: 地図 CRS 確定後は GCP を三角網に使わない選択肢をサポートしなければならない
地図 CRS とワールドファイル値が確定した後、パッケージは GCP を三角網にも使うかどうかを呼び出し側が選べなければならない。

#### Scenario: GCP を三角網に使う
- **GIVEN** 確定済み地図 CRS 状態で、GCP の三角網利用が有効になっている
- **WHEN** 作業変換を構築する
- **THEN** パッケージは、絵図座標系と、その確定 CRS およびワールドファイル値から導出された地図座標系との間で三角網を構築しなければならない

#### Scenario: GCP をコントロールポイント専用にする
- **GIVEN** 確定済み地図 CRS 状態で、GCP の三角網利用が無効になっている
- **WHEN** 作業変換を構築する
- **THEN** パッケージは、GCP を CRS/ワールドファイル導出用コントロールポイントとして保持しつつ、三角網頂点としては使ってはならない

### Requirement: オプションの GCP メタデータは安定した点インデックスを維持しなければならない
V3 データモデルは、各制御点にオプションのメタデータを関連付けられなければならないが、その際にも三角形および制約エッジが参照する座標 tuple のインデックスを変更してはならない。

#### Scenario: メタデータが存在する
- **GIVEN** 一部の制御点が種別やメモなどのメタデータを持つ payload がある
- **WHEN** その payload がシリアライズされる
- **THEN** そのメタデータは `points`、`edges`、`tins_points` が使う元の点インデックスに対応したまま保持されなければならない

#### Scenario: メタデータが存在しない
- **GIVEN** 座標 tuple だけを含む payload がある
- **WHEN** その payload がシリアライズまたはロードされる
- **THEN** パッケージはメタデータを必須とせず、現在の挙動を維持しなければならない

### Requirement: 配布用 payload は再編集不可の意図を宣言しなければならない
ランタイム指向の配布用 payload は、完全な再編集ではなく、変換および配布を目的としたものであることを明示しなければならない。

#### Scenario: ランタイムローダが配布用 payload を読む
- **GIVEN** ランタイム向けの配布用 payload がある
- **WHEN** `@maplat/transform` または他の consumer がそれを読み込む
- **THEN** その payload kind は、完全な編集状態を再構築しなくても変換実行が可能であることを明確に示さなければならない

#### Scenario: エディタが配布用 payload を受け取る
- **GIVEN** 配布用 payload が編集ワークフローに渡される
- **WHEN** エディタがその payload kind を確認する
- **THEN** エディタは完全再編集可能とみなさず、拒否または制限付き動作へ切り替えられなければならない
